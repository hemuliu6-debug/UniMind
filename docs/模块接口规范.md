# 四学科模块统一接口规范（必须遵守）

## 核心规则

1. 模块公开两个函数：`answer(question: str, image: str | None = None) -> str`，`build_tab() -> None`。
2. 模块内通过 `core.pipeline.respond(subject, question, PROMPT, image=...)` 使用公共模型与检索流程，**不得私自初始化 OpenAI 客户端**。
3. `build_tab()` 在 `app.py` 提供的 `with gr.Tab(...)` 内执行，**不创建第二个 Blocks、不调用 launch()**。
4. `answer()` 返回 Markdown 字符串。允许空问题 / 失败的友好提示；不得返回未处理的 Python 异常、原始密钥或 token。
5. 所有个人资料写进对应 `knowledge/<subject>.json`，禁止改动其他组的文件；公共文件由 9 号审核。

## 接口例子

```python
from core.pipeline import respond
from modules._ui import build_subject_ui

PROMPT = "你是某学科助教，请分步骤说明、校验依据，不确定时承认不确定。"


def answer(question: str, image: str | None = None) -> str:
    return respond("physics", question, PROMPT, image=image)


def build_tab() -> None:
    build_subject_ui(
        description="### 物理学习助手",
        example="为什么静电场做功与路径无关？",
        callback=answer,
    )
```

学科代码值只能是：`circuit`、`math`、`physics`、`programming`。数学、物理和编程当前不展示图片框，但其 `answer` 仍保留可选 `image` 形参。若新增图片功能，请先向 9 号申请 UI 变更。

## knowledge/*.json 格式

最外层为 JSON 数组，每张知识卡有以下字段：

```json
[
  {
    "id": "p-004",
    "title": "静电场路径无关",
    "keywords": ["电场", "静电", "做功", "路径无关"],
    "content": "静电场是保守场；该结论不应不加条件推广至随时间变化的感应电场。",
    "source": "小组自编物理知识卡（根据课程内容核对）"
  }
]
```

**填写规范：** `id` 不得重复；标题有区分度；`keywords` 至少 3 个且避免泛词；`content` 保留正确的适用条件；`source` 必须真实可查。示例知识卡尚未指向教材页码，应明确其为小组自编，不能谎称引用某本教材。

## RAG 调用示意

```text
用户 question (+ 可选 image)
    ├── retrieve: search(subject, question)  → 返回最多 2 张知识卡
    └── ask_model(question, system_prompt, context, image)
         → Markdown 回答
    → 展示“检索到的参考资料”
```

目前 `core.retriever.search()` 是关键词检索、不是语义向量检索；`format_source_list()` 仅展示检索结果清单，**不能自动证明回答的每一句都正确引用资料**。

## 变更需要负责人审批的事项

- 修改 API Key 和模型配置、公共客户端或 RAG 规则
- 改动主页布局、各组共享 UI、依赖库版本
- 引入新框架、更换 Python 版本、部署公网服务

## 分工式 Git 审核验收

- 能离线运行；不会调用真实 API；不存在密钥。
- JSON 能通过 Python 解析；每张新卡片被 1 个对应案例检索到。
- 变量与函数符合以上签名；前后端不报错。
- 回答模板可以解释学科特色，而不是完全一样的通用 Prompt。
