# 测试、验收与答辩标准（10 号负责）

## 验收分层

**L1 离线联调：** 无 API Key，全部模块可运行；`python -m unittest discover -s tests -v` 全过；这是架构验证，不代表 AI 准确率。

**L2 在线验证：** 9 号在有额度的开发机将 `DEMO_MODE=0`；用真实 DeepSeek 访问四个模块，记录响应时间、成功/失败以及是否符合问题。

**L3 学科有效性：** 每组至少 5 个样本（共 20 个起），由题目设计者提供参考要点，再由另一位成员盲查回答。建议加 4 条“信息不足/模糊”的问题作为鲁棒性测试。

## 每个案例记录字段

| 字段 | 示例 |
|---|---|
| case_id | circuit-01 |
| 学科 | 模拟电路 |
| 输入问题 | 示波器无波形如何排查？ |
| 输入图片 | 无 / sample1.png（不提交隐私图片） |
| 标准核查要点 | 检查仿真状态、接线、量程 |
| 资料来源 | 项目自编 c-001 |
| 结果 | 通过 / 部分通过 / 失败 |
| 主要问题 | 有依据/计算错误/无依据猜测/格式错误 |
| 备注 | 复现环境与时间 |

## 建议 KPI（都是项目目标，不是已达成）

- 四个 Tab 均可独立回答；图片仅在模电模块是必需能力。
- 每组至少 5 个不同问题（建议总计 20～30 个）。
- 无答案或证据不足时能明确说明，而不是编造具体数值、书籍或页码。
- 对严重 API 异常有可理解的提示，不在网页暴露完整密钥、请求头或敏感响应。
- 四学科至少各准备 1 个稳定的现场 Demo，另外准备 1 个失败案例说明局限。

## 5 分钟演示脚本（按老师规定调整）

| 时间 | 展示 |
|---|---|
| 0:00–0:40 | 背景：不同学科学习工具碎片化、实验答疑成本高 |
| 0:40–1:20 | 一个网页四个 Tab，共用 API 与专业知识卡 |
| 1:20–3:20 | 电路截图分析 → 数学分步求导 → 物理单位检查 → Python 报错分析 |
| 3:20–4:20 | 展示检索到的知识卡与测试结果、错误案例 |
| 4:20–5:00 | 总结架构、团队分工、未来扩展 |

## 现场应展示而不是空喊的创新

1. 分学科专业提示词（可读代码）；
2. 专门的课程知识检索，而非通用聊天；
3. 模拟电路图片 + 文字联合输入；
4. 模块化协作：新增新学科只需实现规定接口即可挂载到统一首页。

**特别说明：** 四个学科页面本身并不保证创新性高；请用具体专业案例、检索证据以及基础模型 vs 专用模块的对比结果论证价值。不要声称已经训练了模型。
